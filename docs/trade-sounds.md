# 入场／止盈／止损成交提示音

这是搞笑功能：成交时播放的是一段搞笑音效，素材见[素材与裁剪](#素材与裁剪)。设置页的开关说明里也这样写。

## 开关

- 「设置 → 交易」的“成交音效”开关管入场、止盈、止损三类音效，对所有账户和交易商生效，默认开启。
- 开关和“跳过交易确认”“键盘下单”存在同一份本机交易设置里。这个开关出现之前保存的设置没有这一项，按开启读取；设置文件损坏读不出来时回到开启，设置页会提示。
- 关闭时正在播放的片段立即停止，排队等待的片段丢弃。关闭期间的成交不会在重新打开后补播；在关闭期间已经成交过的订单，之后再来的成交消息也不播放。

## 播放规则

- 入场：播放 `entry.wav` 一次，0.62 秒。来源视频先按用户指定的约 18 至 20 秒提取，随后根据尾部串音反馈改为 18.53 至 19.15 秒；下一声从约 19.76 秒开始，已排除。
- 止盈：播放 `take-profit.wav` 一次，1.08 秒，只保留来源视频的一个完整重复单元。
- 止损：从 12 个 `stop-loss-*.wav` 中等概率随机选一段，播放一次。不同交易允许随机选到同一段。
- 监听已连接交易商的入场／保护单确认成交，不根据价格触线或最终盈亏正负猜测。止损移到盈利区后成交仍播放止损音效。
- 入场包括可确认的挂单入场、ATM 入场及本应用提交的开仓／加仓；反向下单只减仓时不播，反转订单成交量超过原净仓后才播入场。没有先前挂单证据、ATM 证据或本应用下单记录的外部终态订单不猜测为入场。
- 同一账户的同一订单只通知一次，部分成交和重复消息不重复播放。下单仅被受理、手动平仓、撤单、强平、历史加载、重连快照和重新同步不播放。
- 关联不完整／有冲突时不猜测类型；实时 fill 先到、父子单／ATM 信息后到时，等证据完整后再通知。直接 OCO 需要曾经确认其保护当前净仓，单靠 Stop/Limit 类型不够。
- 声音监听不依赖当前选择的账户或图表品种。短时间出现多个成交时顺序播放，不叠音；断开交易商后丢弃该交易商尚未开始播放的提示。
- 文件随应用打包，不访问 Bilibili、不打开视频、不循环播放。音频失败不阻断交易；单次播放最多等待 10 秒，取消页面播放 effect 时释放原生播放器。
- 监听范围为应用运行、交易连接仍在接收实时事件期间；不新增系统后台保活或推送。通知事件为不重放的尽力传递流，极端拥塞时保留最近 256 个事件，不阻塞成交处理。

## 手动测试

桌面使用以下命令启动隔离的本地模拟窗口：

```bash
./gradlew :composeApp:run --args=--local-demo
```

该参数只在显式指定时启用：使用内存账本，不读取已保存的 Tradovate 凭据，不提供远程登录，关闭后模拟数据清空；普通启动使用 Tradovate 登录流程。模拟行情每秒推进 15 秒，可在顶部暂停。先下市价单测试入场音效，再给持仓设置接近当前价格的止盈／止损来测试保护成交。

## 实现与验证

- `BrokerPlugin.tradeFills`：跨交易商的实时入场／保护成交通知。
- `TradeFillTracker`：服务器 fill、订单关系证据、同步基线与订单去重。同步基线时间按秒取整；时间早于基线的新历史 fill 不播放。
- `DemoBroker`：本地开仓／保护平仓事务提交后发布通知，恢复／重置不补播。
- `TradeSoundController`：随机选音、顺序播放、账户隔离、重复过滤、播放器故障隔离；按 `TradingPreferences.tradeSounds` 决定是否播放。
- 原生播放器：桌面 Java Sound、Android MediaPlayer、iOS AVAudioPlayer；iOS 遵循系统默认音频会话与静音策略，未强制覆盖静音开关。

自动化覆盖事件分类、历史抑制、部分成交、乱序消息、播放排队、取消释放、素材解码与时长。本次 Windows 验证结果：177 项桌面测试通过（其中 28 项音效专项测试），Android debug 构建通过，安装包内 14 个 WAV 与当前源文件逐字节一致（共 905,538 字节）。`iosArm64` 和 `iosSimulatorArm64` 的 Kotlin/Native 编译也通过；Apple 最终链接、模拟器运行和各平台实际听感尚未验证。
