# 连续合约

搜索品种前缀（如 `MES`）或 `@MES` 后，可以选择 `@MES` 连续合约。加载 USD 线性期货规格时，目录同时提供对应的 `@品种` 图表入口；原到期合约入口保留。

- K 线通过 `md/getChart` 请求 `@MES`，历史与实时 K 线独立缓存。全部指标使用这份连续 K 线，不使用单个到期合约历史冒充连续历史，也不在客户端拼接或复权。
- 主力按同品种未到期合约在**上一完整交易日的成交量最大者**确定。`contractMaturity/deps` 与 `contract/ldeps` 枚举候选，按产品 ID 和到期合约代码校验，不使用 `isFront`、最近月份或 suggest 列表顺序选主力。
- `tradingSession/ldeps` 的 `tradeDate`、`startTime`、`endTime` 确定完整交易日。只校验交易起止时间，不要求 `openTime` 晚于 `startTime` 或 `closeTime` 早于 `endTime`。所有候选必须比较同一交易日。通常 DailyBar 请求按该交易日期的 UTC 零点至次日零点前限定；日期来自服务端交易日历，不以设备日期推断。无 `td` 的日线必须带对应日期的 UTC 零点时间戳；存在 `td` 时必须匹配。已有日线必须有完整的买卖方向成交量及历史结束标记，不使用当天尚未完成的成交量。
- 日历尚未发布当前/后续交易日时，只接受结束时间距查询时刻不足 72 小时的最新完整时段。此时所有候选均要求 `RealTime` 模式和有效的实时通道，并从目标交易日零点查询到最新日线，不设置历史上界；出现更新日期的日线即拒绝解析，避免用限定旧日期的查询掩盖日历落后。这个 72 小时上限是数据陈旧保护，不用于推算下一开市日；超时仍阻止下单。日历缺失、重叠、日期矛盾或各候选完整交易日不同仍拒绝。
- 缺少下一时段时，已核实的成交量与实时日线订阅一起保留；同一连接、同一交易日再次校验日历可复用该证据，不重复拉历史。任一候选收到更新日期、成交量修正或无效日线，立即撤销相关主力映射。交易日变化、证据失效或行情重连后重新查询；失败请求清理订阅，后台缓存有容量限制。
- 仅当日线请求成功、回执模式为 `RealTime`、历史通道有效、未发生早到历史包溢出并明确收到 `eoh` 时，允许将该日完整空响应计为零成交量（2026-10-31 用户确认）。失败、超时、权限不足、未结束、格式错误或成交量字段缺失均不能按零处理；全零或最高成交量并列仍无法确认主力。
- 图表、下单面板和确认窗显示连续代码与实际下单代码。Bid/Ask、可下单数量、保证金风控与保护价校验使用实际下单合约。连续历史价格不做额外的价差换算；输入或拖动的限价、SL、TP 按实际合约价格原值提交。
- 市价、限价、Stop 和 OSO 括号单均只发送实际到期合约。连续代码只作为本地来源信息，不能直接到达订单端点。
- 日历覆盖下一时段时，主力结果有效至候选下一交易时段结束或最早合约到期，以较早者为准；同一完整交易日内复用已确认结果。缺少下一时段时，确认结果最多缓存 60 秒，并同时受 72 小时日历保护上限、已知候选下一时段结束和合约到期时间限制。到期后自动刷新，失败时最多每 60 秒重试；重连和同步账户重新查询，提交前校验有效期并在需要时刷新。映射缺失、成交量并列/全零、日历或历史未通过校验、权限不足或查询失败时阻止连续来源新单。提交前发现换月时，拒绝原请求并要求重新确认，不把已确认的旧价格静默发到新合约。
- 每次完整比较最多 200 个候选月份/合约，超出上限会停止自动路由；REST 按 50 个 ID 分批查询并沿用统一节流，首次目录加载也批量读取未缓存的月份规格，缺失或批量失败时使用原有逐项校验路径。日成交量最多三路并发读取，不占用或取消用户当前的图表订阅。连续图表与成交量使用同一套 `md/getChart` 限流处理：若回执不要求验证码且等待时间不超过 30 秒，按服务端指定时间等待并携带票据重试一次；仍限流则明确报错，不当作权限不足或零成交量。查询超时也不会回退到最近月份。未能取得全部候选合约或全部候选的日成交量时，不声称已找到全市场主力。
- 换月更新下单合约并切换新订单草稿；旧持仓、挂单、成交及保护单保留原合约身份。不会自动平仓、移仓或重建保护单。旧合约可在交易列表和原合约图表继续管理。
- 连续行情是否可用、历史深度及换月时间由 Tradovate 行情服务决定。没有权限时不生成替代 K 线；映射失败不阻止尝试读取连续图表。
- 图表、行情列表及订单面板显示每个连续合约自身的核实进度或失败原因，避免其他连接消息覆盖原因后一直只显示“待确认”。重复选择同一失败品种遵守 60 秒重试间隔；主动搜索、同步账户仍可立即重试。

协议依据：[Tradovate 官方 API](https://api.tradovate.com/)、[官方连续合约介绍](https://tradovate.zendesk.com/hc/en-us/articles/360022600113-Do-you-offer-continuous-contracts)。`isFront` 不保证成交量主力，[GC 历史反例](https://community.tradovate.com/t/front-month-determination/2570)。本实现采用用户指定的上一完整交易日成交量规则，不宣称与 Tradovate 连续图表的内部换月规则一致。

常规回归使用模拟协议，不访问保存的账户，也不发送真实交易。覆盖连续历史隔离、实际代码下单与括号单、确认后换月拒绝、映射失败、连续代码直接下单拒绝、日成交量领先者与 isFront 不同、并列/全零/缺失数据拒绝、跨品种候选拒绝、周末和提前闭市、历史包早于订阅回执以及草稿价格保持。显式只读联调另行记录，不代表已验证实际换月或真实订单。

## 周末日历末尾修复（2026-10-31）

用户重新登录 Demo 后，只读读取 `tradingSession/deps` 与 `tradingSession/ldeps`：MES 五个未到期月份均只返回截至 2026-10-30 的时段，最后结束时间为 `2026-10-30T21:00Z`，没有下一交易日。原解析器强制要求存在 `endTime > now` 的时段，因而在周末直接报“交易日历未覆盖当前或后续交易日”，尚未进入成交量比较。此前周末测试人为提供了下周一时段，未覆盖实际响应。

现在按上文的最新日线校验、72 小时数据陈旧上限和 60 秒缓存规则处理缺少下一时段的情况。新增回归覆盖真实周六日期、任一候选缺少后续时段时全部候选校验最新日线、更新日期的日线拒绝、行情权限/成交量/结束标记缺失拒绝、一分钟后刷新、换月拒绝旧订单及刷新失败后清除映射。
