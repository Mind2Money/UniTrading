# 连续合约

搜索品种前缀（如 `MES`）或 `@MES` 后，可以选择 `@MES` 连续合约。加载 USD 线性期货规格时，目录同时提供对应的 `@品种` 图表入口；原到期合约入口保留。

- K 线通过 `md/getChart` 请求 `@MES`，历史与实时 K 线独立缓存。全部指标使用这份连续 K 线，不使用单个到期合约历史冒充连续历史，也不在客户端拼接或复权。
- 主力按同品种未到期合约在**上一完整交易日的成交量最大者**确定。`contractMaturity/deps` 与 `contract/ldeps` 枚举候选，按产品 ID 和到期合约代码校验，不使用 `isFront`、最近月份或 suggest 列表顺序选主力。
- `tradingSession/ldeps` 的 `tradeDate`、`startTime`、`endTime` 确定完整交易日；日历须覆盖已结束和当前/后续交易日。只校验交易起止时间，不要求 `openTime` 晚于 `startTime` 或 `closeTime` 早于 `endTime`。所有候选必须比较同一交易日。DailyBar 请求按该交易日期的 UTC 零点至次日零点前限定；日期来自服务端交易日历，不以设备日期推断。无 `td` 的日线必须带对应日期的 UTC 零点时间戳；存在 `td` 时必须匹配。已有日线必须有完整的买卖方向成交量及历史结束标记，不使用当天尚未完成的成交量。
- 仅当日线请求成功、回执模式为 `RealTime`、历史通道有效、未发生早到历史包溢出并明确收到 `eoh` 时，允许将该日完整空响应计为零成交量（2026-10-31 用户确认）。失败、超时、权限不足、未结束、格式错误或成交量字段缺失均不能按零处理；全零或最高成交量并列仍无法确认主力。
- 图表、下单面板和确认窗显示连续代码与实际下单代码。Bid/Ask、可下单数量、保证金风控与保护价校验使用实际下单合约。连续历史价格不做额外的价差换算；输入或拖动的限价、SL、TP 按实际合约价格原值提交。
- 市价、限价、Stop 和 OSO 括号单均只发送实际到期合约。连续代码只作为本地来源信息，不能直接到达订单端点。
- 主力结果有效至候选下一交易时段结束或最早合约到期，以较早者为准；同一完整交易日内复用已确认结果。到期后自动刷新，失败时最多每 60 秒重试；重连和同步账户重新查询，提交前校验有效期并在需要时刷新。映射缺失、成交量并列/全零、日历或历史不完整、权限不足或查询失败时阻止连续来源新单。提交前发现换月时，拒绝原请求并要求重新确认，不把已确认的旧价格静默发到新合约。
- 每次完整比较最多 200 个候选月份/合约，超出上限会停止自动路由；REST 按 50 个 ID 分批查询并沿用统一节流，日成交量订阅依次读取并清理，不占用或取消用户当前的图表订阅。查询超时也不会回退到最近月份。未能取得全部候选合约或全部候选的日成交量时，不声称已找到全市场主力。
- 换月更新下单合约并切换新订单草稿；旧持仓、挂单、成交及保护单保留原合约身份。不会自动平仓、移仓或重建保护单。旧合约可在交易列表和原合约图表继续管理。
- 连续行情是否可用、历史深度及换月时间由 Tradovate 行情服务决定。没有权限时不生成替代 K 线；映射失败不阻止尝试读取连续图表。
- 图表、行情列表及订单面板显示每个连续合约自身的核实进度或失败原因，避免其他连接消息覆盖原因后一直只显示“待确认”。重复选择同一失败品种遵守 60 秒重试间隔；主动搜索、同步账户仍可立即重试。

协议依据：[Tradovate 官方 API](https://api.tradovate.com/)、[官方连续合约介绍](https://tradovate.zendesk.com/hc/en-us/articles/360022600113-Do-you-offer-continuous-contracts)。`isFront` 不保证成交量主力，[GC 历史反例](https://community.tradovate.com/t/front-month-determination/2570)。本实现采用用户指定的上一完整交易日成交量规则，不宣称与 Tradovate 连续图表的内部换月规则一致。

常规回归使用模拟协议，不访问保存的账户，也不发送真实交易。覆盖连续历史隔离、实际代码下单与括号单、确认后换月拒绝、映射失败、连续代码直接下单拒绝、日成交量领先者与 isFront 不同、并列/全零/缺失数据拒绝、跨品种候选拒绝、周末和提前闭市、历史包早于订阅回执以及草稿价格保持。显式只读联调另行记录，不代表已验证实际换月或真实订单。

## “主力待确认”修复（2026-10-31）

使用用户已有 Demo 登录会话读取真实接口，确认此前模拟数据没有覆盖三种实际响应：

1. MES 时段 `openTime=21:30`、`startTime=22:00`、次日 `endTime=21:00`、`closeTime=21:29`，原先的包含关系校验将正常时段拒绝为“交易时段无效”。
2. DailyBar 历史包没有 `td`，使用 `2026-10-29T00:00Z` 这样的日线日期标签；原先强制要求 `td` 导致正常日线被拒绝。
3. 远月合约可能成功返回同一 historical/realtime 通道 ID，随后只有 `eoh=true`，没有日线。经用户确认，将满足上述完整性条件的空结果计为零。

首次只读采样的交易日为 2026-10-29：MESZ6 成交量 1,438,061，MESH7 为 1,838，MESM7 为 6，MESU7 和 MESZ7 是完整空响应。原始公开合约元数据和行情证据保存在本机 `artifacts/continuous-fix/`，不包含令牌或账户信息，不提交凭据。

可显式运行 `./gradlew :composeApp:tradovateReadOnlyLoginProbe -PconfirmTradovateReadOnly=true -PprobeSavedContinuous=true`。该入口读取本机加密保存的 Demo 会话，通过实际 Broker 检查 MES、MNQ、MGC；传输层仅放行列明的读取和行情订阅端点，所有订单端点（包括 dryrun）均被拒绝。正常测试套件不会自动运行此联网入口。
