# 连续合约

搜索品种前缀（如 `MES`）或 `@MES` 后，可以选择 `@MES` 连续合约。加载 USD 线性期货规格时，目录同时提供对应的 `@品种` 图表入口；原到期合约入口保留。

- K 线通过 `md/getChart` 请求 `@MES`，历史与实时 K 线独立缓存。全部指标使用这份连续 K 线，不使用单个到期合约历史冒充连续历史，也不在客户端拼接或复权。
- 主力按同品种未到期合约在**上一完整交易日的成交量最大者**确定。`contractMaturity/deps` 与 `contract/ldeps` 枚举候选，按产品 ID 和到期合约代码校验，不使用 `isFront`、最近月份或 suggest 列表顺序选主力。
- `tradingSession/ldeps` 的 `tradeDate`、`startTime`、`endTime` 确定完整交易日。只校验交易起止时间，不要求 `openTime` 晚于 `startTime` 或 `closeTime` 早于 `endTime`。所有候选必须比较同一交易日。DailyBar 请求始终按该交易日期的 UTC 零点至次日零点前限定；日期来自服务端交易日历，不以设备日期推断。无 `td` 的日线必须带对应日期的 UTC 零点时间戳；存在 `td` 时必须匹配。早于目标交易日的日线表示该月份当日无成交：当日未成交的远月会返回其最近一根旧日线（实测 GCN7 对 2026-10-30 返回 2026-10-28），按零成交量处理，仍要求 `RealTime` 回执和 `eoh`；较新日期的日线可能仍在形成，不参与目标日排名，也不因其出现而拒绝解析；无 `td` 的非零点日线仍拒绝。已有日线必须有完整的买卖方向成交量及历史结束标记，不使用当天尚未完成的成交量。
- 日历尚未发布当前/后续交易日时，只接受结束时间距查询时刻不足 72 小时的最新完整时段。此时所有候选均要求 `RealTime` 模式和有效的实时通道，仍只查询最后已确认结束的交易日，并在 15 分钟后重新读取日历和核实该日成交量。当前日线已出现不代表其交易日已经结束。缺少后续时段时，仅凭日线日期无法判断是否遗漏另一个已结束交易日，结果受服务端日历覆盖范围限制。这个 72 小时上限是数据陈旧保护，不用于推算下一开市日；超时仍阻止下单。日历缺失、重叠、日期矛盾或各候选完整交易日不同仍拒绝。
- 已完成交易日的各合约成交量按“合约 + 交易日”缓存并持久化到本机（非敏感行情数据，最多 2,000 条、14 天），重新核实与重启只查询缺失的月份。每次日线查询读完即取消订阅，不保留任何日线图表订阅。缺少下一时段时，排名额外对领先合约做一次限定目标交易日的成交量查询；领先合约成交量与缓存不一致视为修正，清除该品种当日缓存并全部重新查询。交易日变化、查询失败或行情重连后重新查询。
- 仅当日线请求成功、回执模式为 `RealTime`、历史通道有效、未发生早到历史包溢出并明确收到 `eoh` 时，允许将该日完整空响应计为零成交量（2026-10-31 用户确认）。固定日期查询不携带根数限制；即使只返回较新日期日线，只要符合上述历史完整性条件，目标日没有日线仍按零成交处理，较新日线的成交量不参与排名。失败、超时、权限不足、未结束、格式错误或目标日成交量字段缺失均不能按零处理；全零或最高成交量并列仍无法确认主力。
- 图表、下单面板和确认窗显示连续代码与实际下单代码。Bid/Ask、可下单数量、保证金风控与保护价校验使用实际下单合约。连续历史价格不做额外的价差换算；输入或拖动的限价、SL、TP 按实际合约价格原值提交。
- 市价、限价、Stop 和 OSO 括号单均只发送实际到期合约。连续代码只作为本地来源信息，不能直接到达订单端点。
- 日历覆盖下一时段时，主力结果有效至候选下一交易时段结束或最早合约到期，以较早者为准；同一完整交易日内复用已确认结果。缺少下一时段时，确认结果最多缓存 15 分钟（新交易时段不可能在两次检查之间开始并完成），并同时受 72 小时日历保护上限、已知候选下一时段结束和合约到期时间限制。到期后自动刷新，失败时最多每 60 秒重试；重连和同步账户重新查询，提交前校验有效期并在需要时刷新。映射缺失、成交量并列/全零、日历或历史未通过校验、权限不足或查询失败时阻止连续来源新单。提交前发现换月时，拒绝原请求并要求重新确认，不把已确认的旧价格静默发到新合约。
- 每次完整比较最多 200 个候选月份/合约，超出上限会停止自动路由；REST 按 50 个 ID 分批查询并沿用统一节流，首次目录加载也批量读取未缓存的月份规格，缺失或批量失败时使用原有逐项校验路径。日成交量最多三路并发读取，不占用或取消用户当前的图表订阅。连续图表与成交量使用同一套 `md/getChart` 限流处理：若回执不要求验证码且等待时间不超过 30 秒，按服务端指定时间等待并携带票据重试一次；仍限流则明确报错，不当作权限不足或零成交量。服务端以 “Limit for a number of simultaneous chart requests reached” 拒绝时不会建立订阅，间隔 2 秒、4 秒最多重试两次。查询超时也不会回退到最近月份。未能取得全部候选合约或全部候选的日成交量时，不声称已找到全市场主力。
- 换月更新下单合约并切换新订单草稿；旧持仓、挂单、成交及保护单保留原合约身份。不会自动平仓、移仓或重建保护单。旧合约可在交易列表和原合约图表继续管理。
- 连续行情是否可用、历史深度及换月时间由 Tradovate 行情服务决定。没有权限时不生成替代 K 线；映射失败不阻止尝试读取连续图表。
- 图表、行情列表及订单面板显示每个连续合约自身的核实进度（“正在核实主力 n/m”）或失败原因，避免其他连接消息覆盖原因后一直只显示“待确认”。重复选择同一失败品种遵守 60 秒重试间隔；主动搜索、同步账户仍可立即重试。核实被取消（例如离开行情页）时恢复取消前的映射与有效期，不留在“核实中”。
- 最近一次确认的主力合约名按连续代码持久化，只作为行情列表的报价来源（`Instrument.quoteSymbol`）：核实期间、核实失败及重启后尚未核实时继续显示其报价并标注“核实中/待确认”。订单、可下单数量、预览及确认窗只使用本次有效的 `tradeSymbol`，不使用该记录。

协议依据：[Tradovate 官方 API](https://api.tradovate.com/)、[官方连续合约介绍](https://tradovate.zendesk.com/hc/en-us/articles/360022600113-Do-you-offer-continuous-contracts)。`isFront` 不保证成交量主力，[GC 历史反例](https://community.tradovate.com/t/front-month-determination/2570)。本实现采用用户指定的上一完整交易日成交量规则，不宣称与 Tradovate 连续图表的内部换月规则一致。

常规回归使用模拟协议，不访问保存的账户，也不发送真实交易。覆盖连续历史隔离、实际代码下单与括号单、确认后换月拒绝、映射失败、连续代码直接下单拒绝、日成交量领先者与 isFront 不同、并列/全零/缺失数据拒绝、跨品种候选拒绝、周末和提前闭市、历史包早于订阅回执以及草稿价格保持。显式只读联调另行记录，不代表已验证实际换月或真实订单。

## 按最后一个完整交易日排名（2026-11-03）

截图中当前日期日线（2026-11-03）已经形成，但对应交易日尚未结束。原实现虽从日历中选出最后结束的时段，日历末尾分支却改查最新一根日线，并因日期较新而拒绝整轮排名。

现在所有候选始终查询日历中 `endTime <= now` 的最后一个完整交易日，按该日成交量比较。即使当前日成交量已超过昨日，也不提前换主力；共享实时通道送来的较新日线不进入排名。到达已知下一时段结束时间时，重新查询刚结束的交易日。保留日历完整性、72 小时陈旧上限、15 分钟末尾刷新、成交量修正与历史结束校验。
