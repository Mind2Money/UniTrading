# Tradovate 登录交接修复

> 版本记录：1.1.1。本文的测试数量、只读实测和产物对应当时版本；当前实现与验证范围见 [current-status](current-status.md)。

日期：2026-10-28。范围：修复用户已在官方网页登录、主程序仍显示等待的故障。只改 UniTrading；`BatchTradovate` 作为只读参考，不读取其数据目录、浏览器资料或凭据，不发送交易。

## 已定位的原因

1. UniTrading 将认证域名错误绑定到所选交易环境，Demo 时漏掉 `live.tradovateapi.com` 的正常认证响应。参考 `BatchTradovate/src/tradovate/hosts.mjs:4,26–32`、`browser-login.mjs:42–82`：认证/续期走共享 live 域名，交易环境由用户选择，只有响应明确声明冲突环境时才拒绝。
2. Desktop 管道只在收到手动 `DONE` 并且窗口退出后才返回会话；native host 没有自动完成条件。网页登录成功因此一直被当作“等待登录”。
3. 行情连接强制要求独立 `mdAccessToken`；参考 `session.mjs:83`、`quotes.mjs:1–7` 与 `chart-feed.mjs`，行情使用同一账户访问令牌连接所选环境的 md/ md-demo 网关。
4. 账户同步未显式设置 `splitResponses:false` 和 `entityTypes`；参考项目明确说明默认实体订阅为空。只检查集合存在仍不足以证明收到完整数据。
5. 实际只读诊断已复现“令牌交接成功、行情连接成功、账户目录 0 条”。原实现将账户记录的 `userId` 与认证用户直接比较，这会排除授权/受托账户；改用当前环境 `account/list` 返回的授权账户 ID，账户流请求不再传入来自认证域名的用户筛选器。

6. 后续只读复核已取得 2 个授权账户和实时报价，但服务器返回的 513 根 K 线均被时间解析丢弃。诊断只记录了时间格式形状 `####-##-##T##:##Z`，确认服务端省略秒数；补齐明确为零的秒数后，实际读取到 155 根历史 K 线。没有猜测缺失时区或生成替代行情。

## 修复方式

- 分离认证地址与交易地址。允许来自明确官方认证域名的响应，不根据 live 认证主机把 Demo 账户切成 Live。支持 `d` 包装、`accessToken/access_token/token`、`userId/user_id`、JWT/相对有效期等正常响应形态。
- 账户令牌即满足登录交接条件；不等待行情令牌。Desktop 参照参考项目保留密码保存窗口：首次最多 60 秒，观察到密码库元数据变更或已有完成标记时短暂等待后自动返回；只读文件大小/时间，不读密码库内容。支持“立即返回”，明确取消仍丢弃会话。
- Android 收到有效会话后自动提交系统 autofill 上下文，待保存提示处理后自动返回；无需再点“完成登录”。
- 显示可区分的阶段：网页登录 → 已取得会话/等待保存密码 → 账户授权 → 完整账户同步 → 合约/资金加载 → 行情授权。连接等待有超时，可取消。
- 原生主机改为版本化输出，避免覆盖用户仍在使用的旧登录窗口，不删除保存的浏览器资料。
- 使用账户访问令牌建立行情连接；市场数据拒绝单独报告，不把它重新解释为未登录。
- `user/syncrequest` 显式订阅 account/order/position 等实体类型，读取当前授权上下文而非显式指定认证域用户 ID；请求完整响应，缺少关键集合时明确报错。
- 先从所选交易环境读取 `account/list`，按服务器授权账户 ID 映射目录，支持受托账户和没有 owner 字段的记录；不再用 owner/userId 相等作为权限依据。

- 行情图表订阅 ID 与数据库实体 ID 分开处理，保留原始 wire ID，兼容小数、科学计数法及字符串；不会先转 Long 丢弃。
- 图表推送即使带关联 `i` 字段也按事件处理；K 线时间同时支持 ISO 字符串、只精确到分钟的 ISO（例如 `2026-10-28T12:35Z`）和 epoch 毫秒。没有时区的字符串仍拒绝，不擅自猜测时区。

## 只读诊断入口

这是独立手动任务，不会随自动测试运行；仅允许 Demo，传输层明确拒绝订单 API。窗口只使用 UniTrading 自己保存的浏览器 profile，不读取 BatchTradovate 的数据。

```bash
./gradlew :composeApp:tradovateReadOnlyLoginProbe -PconfirmTradovateReadOnly=true
```

结果仅输出账户/合约/行情/历史数量和阶段，不输出令牌、账号名称或资金数额。`LOGIN_HANDOFF_OK` 仅证明会话交接成功；最终 `READ_ONLY_RESULT.verified` 只有在账户、报价和历史都取得时为真，否则任务以非零退出。

## 最终只读实测

已通过 UniTrading 自己的官方登录窗口完成 Demo 登录和自动交接。浏览器自身自动填充了保存的凭据；诊断只点击官方 Login 按钮，未读取密码字段、未导出令牌。

最终结果：`connected=true`、`accountCount=2`、`instrumentCount=2`、`quoteAvailable=true`、`historyBars=155`、`sentOrderRequests=0`。只读传输层未发现任何写入尝试。这里验证了真实的会话→账户→行情/历史链路；不代表真实下单、改价或成交已经联调。

回归结果：86 项 JVM/KMP/Compose 测试通过，0 失败、0 跳过；原生登录 host 的 52 项断言通过，Android 1.1.1 调试包构建成功。

旧版本 1.1.0 的手动交接窗口不会被覆盖或清空资料。重启主程序加载 1.1.1 后使用新窗口。

## 验证

- 回归“Demo 选择 + live 认证响应 + 没有 mdAccessToken”这一完整链路。
- 原生自动完成状态机覆盖首次保存、记住登录、超时自动返回、重复令牌不重置等待及取消。
- 管道测试覆盖自动 DONE、异常退出、取消、分阶段状态；不输出真实令牌。
- 验证认证续期仍请求 live 域名，账户与行情流仍为所选环境。
- 验证账户目录来自服务器授权列表，支持账户 owner 与认证用户不相等的授权关系；拒绝未出现在授权目录中的账户。
- 验证完整快照校验、原有 Demo/订单安全测试及 Android 构建。
- 额外提供显式启用的 Demo 只读诊断任务，传输层拒绝所有订单端点；只输出阶段、记录数量和报文形状，不输出令牌、账号标识、余额或成交价格。
- 不在测试中使用真实订单。用户实际登录后的账户/行情读取只在应用内进行，凭据不进入工具输出或日志。
