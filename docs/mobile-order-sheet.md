# 手机下单界面

手机和紧凑窗口（宽度小于 900dp 或高度小于 600dp）的下单界面在「设置 → 交易 → 下单界面」里三选一，默认是上滑面板：

| 界面 | 设置里的说明 | 与图表的关系 |
| --- | --- | --- |
| 上滑面板（默认） | 从底部上滑，可拖动收起 | 盖在图表上，最小化和展开之间图表大小不变 |
| 停靠下单栏 | 停在图表下方或右侧，不遮挡 K 线 | 占用自己的位置，图表随之变矮，横屏展开时变窄 |
| 独立弹窗 | 在对话框中下单 | 对话框；收起后草稿留在图表上 |

选择立即保存在本机 `trading-preferences-v1`。桌面设置里也有这一行，只影响紧凑窗口。三种界面共用同一份草稿、同一个下单表单 `OrderForm` 和同一套校验与确认。上滑面板和停靠下单栏打开时，图表上方的登录和子账户栏隐藏，所以它们展开时在品种下面写出账户名。代码在 [MobileTradePanel.kt](../composeApp/src/commonMain/kotlin/com/unitrading/ui/MobileTradePanel.kt)（上滑面板 `MobileOrderSheet`，停靠下单栏 `MobileOrderDockLayout` / `MobileOrderDock`）、[TradingPanels.kt](../composeApp/src/commonMain/kotlin/com/unitrading/ui/TradingPanels.kt)（弹窗用的 `OrderTicket`）和 [TradingScreen.kt](../composeApp/src/commonMain/kotlin/com/unitrading/ui/TradingScreen.kt)。

## 上滑面板

参考用户提供的 8.24 秒 MT5 录像：0.00 秒为关闭；约 0.25–1.00 秒及 5.50–8.00 秒为最小化；约 2.00–3.25 秒为展开。其余高度为拖动过程，不增设停靠状态。

使用 Compose Material 3 官方 `BottomSheetScaffold` 和 `rememberStandardBottomSheetState`，通过组合封装复用官方手势、吸附、嵌套滚动和无障碍展开/收起。没有复制官方源码或自制拖动状态机。参考：[官方实现](https://github.com/JetBrains/compose-multiplatform-core/blob/jb-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/BottomSheetScaffold.kt)。

| 应用状态 | 表现与操作 |
| --- | --- |
| CLOSED | 关闭 Sheet，显示原有下单入口和导航。明确关闭会清空本次草稿。 |
| MINIMIZED | 官方 PartiallyExpanded，112dp：拖动柄、品种、数量/方向摘要、SL/TP、提交/关闭入口、订单类型与买卖方向两组分段按钮。图表可操作；类型、方向和保护开关直接修改同一份草稿。子账户开启风险计算手数时，摘要写算出的数量；子账户订单风控决定的 SL/TP 在这里只显示、不能切换。 |
| EDITING | 官方 Expanded，正常竖屏占可用高度 56%，可用高度低于 550dp 或键盘展开时使用全部可用高度。头部保留订单类型分段按钮，品种下面写账户名，方向由带实时价格的买卖按钮选择。表单独立滚动，确认入口固定在面板底部。 |

关闭、最小化和展开共享同一个官方 Sheet 状态，打开从 Hidden 原生动画进入，关闭完成后再清空草稿。图表的底部占位连续变化，导航栏淡入淡出；最小化与展开的头部控件交叉淡化，不提前替换整张面板。手势只能在这两个位置吸附，快速下滑也不丢弃草稿。图表没有遮罩，点击图表不会收起面板。激活下单时以面板替代底部导航；关闭后恢复导航。最小化和展开之间图表布局不变。

点击品种区或向上拖动可展开面板。最小化时切换方向会按新方向重算限价或突破价。提交箭头按当前草稿发起下单；默认打开订单确认框，开启“设置 → 交易 → 跳过交易确认”后直接提交；草稿无效或请求处理中禁用。取消确认后保留最小化状态和草稿。

返回键优先关闭键盘；无键盘时，展开退到最小化，最小化再返回关闭。关闭按钮在请求处理中禁用。买卖、订单类型、SL/TP、数量和图表拖线均只修改草稿，下单时始终校验参数，并按“跳过交易确认”设置决定是否显示确认框。

## 停靠下单栏

- 竖屏：打开后停在图表下方，图表让出这块高度。展开时高度为可用高度的 47%（至少 276dp，最多 376dp）；展开“更多设置”后为 56%；键盘打开时为 75%（至少 188dp）。图表至少保留 155dp（窗口很矮时为一半高度）；键盘打开时至少保留 72dp（窗口很矮时为五分之一高度）。
- 横屏（使用侧边导航的横屏窗口）：展开时停在图表右侧，宽度为侧边导航右侧区域的 42%，不小于 280dp（区域很窄时为它的一半），不超过它的一半；最小化时回到图表下方。
- 最小化：图表下方 97dp 的两行，内容与上滑面板最小化时相同（品种、数量/方向摘要、SL/TP、提交和关闭、订单类型与买卖方向），没有拖动柄。
- 没有拖动手势，也没有过渡动画。打开、最小化、关闭、键盘弹出和展开“更多设置”都会立即改变图表的大小。
- 标题：普通合约写品种；连续合约写成“@MES · MESZ6”，主力还没确定时写“@MES · 正在核实主力 …”、“@MES · 主力无法确认：<原因>”或“@MES · 主力待确认”。展开时标题下面是账户名，最小化时是数量和方向。
- 表单：买卖按钮、数量加减和输入、限价或突破价、SL/TP 开关和价格始终显示。数量滑动条、“设置参考 SL / TP”和“清除”、预估与合约信息、底部的入场摘要放在“更多设置”里。“更多设置”展开还是收起保存在本机，下一单和重启后照旧；保存失败时退回保存着的状态，设置页的“交易”一组显示保存失败。
- 最小化时表单和上滑面板一样保留着，只是不占位置、不显示，读屏读不到，也点不到、键盘切换不到。再展开时草稿、“更多设置”、“预估与合约信息”的展开状态和滚动位置都和最小化前一样。
- 关闭和返回与上滑面板相同：“×”（关闭并放弃本次下单）丢弃草稿，请求处理中不可用；系统返回在展开时最小化，最小化时关闭；键盘打开时返回先关闭键盘。

## 独立弹窗

- 点“下单”在对话框里打开完整表单：订单类型、买卖按钮、数量和滑动条、SL/TP、参考 SL/TP，预估与合约信息默认展开。对话框最宽 420dp，高度为窗口的 94%；标题“新建订单”，下面写账户、品种和结算币种。
- 右上角“×”（返回图表）、系统返回、点对话框外面和“到图表调整”都只收起对话框，草稿保留：图上的草稿入场线和 SL/TP 线仍可拖动并回填。请求处理中“到图表调整”不可用，其余三种仍可以收起。
- 收起后底部栏的按钮写“继续下单”，点它打开同一份草稿。这时再按系统返回丢弃草稿，与最小化的上滑面板和停靠下单栏相同；请求处理中不响应，键盘打开时返回先关键盘。
- “取消订单”丢弃草稿，图上草稿线的“×”也会丢弃。下单被受理后草稿结束，下次打开是新订单，按钮回到“下单”。
- 下单确认框出现时弹窗暂时隐藏，取消确认后回到弹窗。

## 三种界面共用的规则

“跳过交易确认”默认关闭，按本机保存并适用于所有账户。开启后，下单、平仓、撤单直接提交；图表上的挂单入场价、持仓 SL/TP 和挂单 SL/TP 在拖动松手时提交。列表中的改单入口仍打开输入框，点击“应用改价 / 应用修改”提交，不会逐字提交输入中的价格。参数、版本和交易商能力校验、提交中防重复点击、拒单提示与草稿保留继续生效。重置模拟数据、清除登录，以及账户页的“平仓此子账户”“平仓全部子账户”不受这个开关影响，始终要确认。设置里这一行的说明跟着选中的子账户：一般写“开启键盘下单时按键即成交”；子账户按风险计算手数时，写这个子账户上按键只打开下单栏、不会直接下单。

下单确认框的内容放不下时（例如横屏手机）可以上下滚动，“取消”和确认按钮始终在底部。确认按钮不可用时，说明原因的错误排在券商提示前面。

子账户开启订单风控时，三种界面的表单都多一行自动止损止盈价格或算出的数量，见[子账户风控](account-risk-lock.md#订单风控)。

## 验证

- 上滑面板（1.5.0 及之前的记录）：原生上/下滑、重复下滑、无障碍收起、紧凑栏切换类型与保护、恢复数量、图表拖线回填、关闭重置、确认成功关闭、拒单保留、横屏与大字体、Android 键盘/返回键。截图和验证日志保存在 artifacts/mt5-sheet/，不入库。
- 2026-11-12 加入停靠下单栏和独立弹窗时，上滑面板按 1.5.0 的代码恢复，只多了上面写的账户名、算出的数量和由订单风控决定的 SL/TP 开关。`MobileSheetMotionTest`（与 1.5.0 相同）和 `MobileLayoutTest` 在默认的上滑面板下通过。停靠下单栏和独立弹窗由 `MobileOrderDockTest`、`MobileOrderPagesTest`、`MobileOrderDockResizeTest` 在桌面测试中覆盖。独立弹窗的系统返回由测试自己的返回事件分发器发出（收起弹窗，再丢弃收起后的草稿），没有经过 Android 的返回键。
- 未验证：这一版没有在 Android 设备或模拟器上运行，只做了编译检查；三种界面在真机上的手势、键盘和系统返回都没有试过。
