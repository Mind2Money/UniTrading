# UniTrading：Kotlin Multiplatform 本地交易终端实施计划

> 文档类型：初版历史设计。当前默认无模拟券商，已接入 Tradovate、加密会话保存及可配置主题；旧阶段要求不代表当前承诺。当前状态见 [current-status](current-status.md)，未完成项见 [实现核对](implementation-audit.md)。

日期：2026-10-27 制定，2026-10-28 更新。状态：Desktop/Android 本地 Demo 已实现并验证；iOS 工程未验证。本计划先于业务代码写入，以下阶段描述保留为实施基线，实际结果以 [验证记录](verification.md) 为准。

> 范围调整：2026-10-27 先以 Desktop 完成基础功能；2026-10-28 用户再次确认 **Android 也纳入**。本次验收包含 Windows Desktop 与 Android；iOS 保留工程骨架，因无 Mac/Xcode 不声明编译或运行通过。

## 1. 背景与目标

从空仓库建立参考 MT5 工作流的跨平台交易终端。首版完成可在本地操作、可复现测试的模拟交易闭环，并保留交易商扩展接口。品种、合约规格、历史 K 线、实时报价、账户状态和交易回执全部由交易商插件提供，UI 不内置交易商数据或自行撮合。

已确认的用户选择：

- 目标平台：Windows 桌面 + Android + iOS。
- 交易商形式：编译期接口注册；不做运行时安装 JAR/动态库。
- 每个交易商可以提供多个账号；账号之间的资金、订单、仓位和历史隔离。
- 当前阶段仅本地 Demo 交易，不连接真实资金账户。
- 实现前先将计划写入 `docs`。

主要交付目标：同一共享核心和共享 UI，通过三个原生入口运行；用户可以选择交易商和账号、查看行情、预览订单、执行模拟交易，在图表查看持仓与历史成交，并通过拖动编辑 SL/TP。

## 2. 范围与边界

### 首版必须包含

- 独立交易商插件 API、注册表、能力声明和错误模型。
- 至少两个独立注册的模拟交易商实例，每个至少两个账号，能体现不同品种目录/交易规格以及账号隔离。
- 交易商生成并提供离线、可复现的模拟报价与同源历史行情；所有模拟内容明确标识。
- 行情列表、品种搜索、交易商/账户切换、报价状态与时间戳。
- K 线、周期切换、十字线、缩放/水平浏览、回到最新与 OHLC 数据表。
- 市价交易、基础限价/止损挂单、撤单、持仓全量平仓及 SL/TP。
- Limit/Stop 入场线可拖动：草稿拖动只改表单与预估；已挂单拖动先预览确认，再按版本原子修改入场价。保留原 SL/TP 和类型，重新校验价格规则；成交或撤销后不得继续修改。
- 对冲账户模型：同品种多个仓位可独立存在和管理；不混入净额结算语义。
- 下单前在表单和图表显示预计盈亏、保证金、费用和风险收益关系。
- 图表显示当前持仓、保护线、历史开/平仓标记；SL/TP 可拖动预览、确认和提交。
- 本地状态保存/恢复、显式重置 Demo、确定性领域测试。
- Windows 桌面、Android、iOS 入口；移动端采用适应窄屏的交互，不照搬桌面三栏。

### 明确不在首版承诺内

- 真实券商/交易所接入、真实鉴权、出入金、生产资金安全或合规能力。
- 运行时热安装插件、第三方插件沙箱、插件市场。
- 完整 MT5 协议兼容、MQL/EA、策略回测、跟单、技术指标库和高级画线工具。
- 交易所订单簿撮合、部分成交、部分平仓、净额账户、复杂订单和实盘级滑点/流动性模型。
- 多币种资金换算、股票公司行为、复杂期权/期货结算与隔夜费体系。
- 不在 Windows 上声称已完成 iOS 构建、签名、模拟器或真机测试。

## 5. 模块与交易规则

### 模块依赖

```text
androidApp / iosApp / desktopMain
                  ↓
              composeApp
           ↙             ↘
       broker-api ← demo-broker
```

- `broker-api`：纯共享领域模型、定点数工具、交易商/账户接口、能力声明、预估与命令结果。不得依赖 Compose 或 JVM 专属类型。
- `demo-broker`：实现插件接口，拥有模拟报价、K 线、账号账本、撮合、历史和可序列化快照；UI 无权直接修改账本。
- `composeApp`：共享工作台、图表、表单与交互状态；平台 source set 提供桌面/iOS 入口和存储适配。
- `androidApp`：Android Activity、清单、平台持久化接线；`iosApp` 提供 SwiftUI 容器与 Xcode 工程。
- 注册表只接受唯一交易商 ID。Demo 插件使用同一个实现的不同配置，至少注册两个交易商，每个两个账号；插件协议不依赖这些配置。

### 账户、状态与请求边界

- 交易商提供品种目录和行情流；每个账号由独立 `AccountSession` 暴露状态和命令。
- 账号身份为交易商 ID + 账号 ID；品种身份包含交易商作用域，不能仅凭 EURUSD 字符串跨交易商复用状态。
- 交易命令串行处理；账户状态通过不可变快照/StateFlow 更新。切换账号取消旧订阅，清空订单草稿、保护价编辑和历史选择。
- 下单、平仓、撤单和保护价修改均带 requestId，插件缓存结果实现幂等；恢复时保留已执行请求标识。
- 修改保护价带仓位版本。报价更新不改变仓位编辑版本；保护价已被修改或仓位已平仓时拒绝过期提交。

### 精度与首版金融口径

- 首版账号结算币种统一为 USD，品种只选择报价与盈亏均为 USD 的线性合约；其他币种/非线性合约明确不支持。
- 价格使用 `Long` 整数 tick；数量使用 `Long` 个 0.01 手；金额使用 `Long` 微美元（1 USD = 1,000,000）。`Double/Float` 只用于绘制坐标，不用于账本。
- 合约规格提供价格小数位、tickSize、每手每 tick 价值、数量范围/步长、杠杆、最小保护距离、每手单边手续费。
- 乘法检查溢出；输入越界直接拒绝。金额展示到分，内部保持微美元；保证金计算向上取整，费用/盈亏按明确规则取整。
- 多头毛盈亏 =（平仓 tick − 入场 tick）× 每手 tick 价值 × 手数；空头方向相反。净盈亏扣除开/平仓手续费；开仓手续费即时扣余额。
- 保证金按开仓名义金额/杠杆锁定；净值 = 余额 + 持仓毛浮盈亏，可用保证金 = 净值 − 已用保证金。无仓位时保证金比例显示“—”。
- 低于 Demo 强平阈值时按最亏损仓位先平仓；这是简化演示规则，不宣称与具体交易商一致。

### 成交和触发

- 市价买入 Ask、卖出 Bid；多头按 Bid 平仓，空头按 Ask 平仓。预估、浮盈亏与撮合使用同一口径。
- Buy Limit 在 Ask ≤ 限价时触发；Sell Limit 在 Bid ≥ 限价时触发，按可成交报价执行，不劣于限价。
- Buy Stop 在 Ask ≥ 触发价时触发；Sell Stop 在 Bid ≤ 触发价时触发，按触发后的实际报价成交，允许跳空。
- 多头 SL/TP 看 Bid，空头 SL/TP 看 Ask；穿越后按实际退出报价执行，不能强行按保护线价格成交。
- 每个 tick 按确定顺序处理已有仓位保护、挂单触发、强平及状态发布；新开仓当 tick 的保护也要检查，避免跳空后遗漏。
- 挂单不预占保证金，界面明确告知；触发时重查资金和有效保护价，不足则拒绝并记录原因。
- 不支持同一条 OHLC 内臆测价格路径；撮合只处理实际生成的有序 tick，历史 K 线不参与倒推成交。
- 断开/过期报价拒绝交易；订单预估不是报价锁定，提交时使用最新状态重新校验。

### 行情、保存和恢复

- 交易商使用固定种子生成模拟 tick，统一聚合 M1/M5/M15/H1；初始历史来自同一价格序列，切换周期不重新抽样。
- 模拟时钟与真实时间分开，UI 明示模拟时间和速率；暂停/退出时不模拟后台真实市场，不补造离线成交。
- 保存版本化快照，包括余额、仓位、挂单、历史、请求结果、ID 序列、模拟时钟/随机状态与行情历史。
- 平台存储写入完整快照，桌面/Android 使用临时文件替换；损坏快照不静默覆盖，显示错误并允许显式重置。
- 恢复不重新注入示例交易。首次初始化的示例仓位与历史也必须由 Demo 撮合产生，并标为演示数据。

### 核心验收案例

- 买/卖开平仓点差与手续费准确；0.01 手和不同 tickSize 不丢精度；超大输入拒绝而非溢出。
- 四种基础挂单按正确 Bid/Ask 触发；跳空保护按实际报价成交；资金不足的挂单触发被拒绝。
- 多仓位独立保护、错误方向/过近保护拒绝、盈利中的 SL 可锁定利润。
- 重复请求不重复成交，仓位过期修改拒绝；切换账号/交易商不泄漏状态。
- 余额/净值/保证金/强平一致；一次保存恢复后账本和随机序列连续，损坏快照有明确错误。
- K 线跨周期聚合一致，历史标记只能对应实际生成的成交。

## 6. UI 与交互

详见 [UI 与图表交互计划](ui-and-chart-design.md)。核心原则：

- 深蓝灰工作台，蓝/铜行情方向编码，图表优先；避免模板化统计首页。
- 桌面为行情 + 主图 + 下单 + 底部交易终端；手机为分区导航 + 图表 + 下单面板。
- 所有下单/保护价调整先预览再确认；回执成功前不伪装为已生效状态。
- 将已生效持仓、历史成交与下单草稿视觉分离。
- 账户切换取消旧订阅与编辑草稿，清除旧账户图层。
- 无效输入、报价过期、断连、提交中、拒单和空列表必须有明确状态。

## 8. 验证策略

### 领域自动测试

由第 5 节定义的规则驱动，包括精度、Bid/Ask、订单触发、SL/TP、保证金、请求幂等、多账号隔离、状态恢复和行情时间一致性。

### 图表与 UI 测试

- 价格/像素互转、tick 吸附、空数据/单条/恒价、缩放边界与标签命中。
- 下单草稿变更时重新估算，输入无效时阻止提交。
- 保护线拖动确认/取消/拒绝，拖动中报价刷新、仓位关闭及账户切换。
- 当前仓位与历史图层的过滤和列表一致性。
- 宽屏与窄屏语义节点及关键操作；不能只检查编译。

### 人工操作路径

1. 启动应用，确认“本地模拟”与当前交易商/账户。
2. 切换两个交易商与多个账户，核对品种目录和资金独立。
3. 选择品种，切换周期、缩放/浏览历史、检查十字线和 OHLC 数据表。
4. 输入一笔带 SL/TP 的买单，核对预计结果和图表草稿；确认后出现仓位。
5. 拖动该仓位的 SL/TP，分别取消和确认；检查原价、更新价、预估及活动记录。
6. 下反向仓位和基础挂单，观察触发/撤单；不得因切换品种串改仓位。
7. 平仓，检查余额、实现盈亏、历史开/平仓标记；切换账户确认数据不泄漏。
8. 重启恢复状态，确认未重复执行订单；重置 Demo 时验证二次确认。
