# UniTrading UI 与图表交互计划

> 文档类型：初版历史设计。固定深色、本地模拟及文字底栏等方案已由 1.1.4 的登录优先、可配置主题和 Material 3 导航替代。实际图表能力与尚未完成项见 [当前状态](current-status.md) 和 [实现核对](implementation-audit.md)。

状态：实施前设计基线，2026-10-28 更新为 Desktop + Android 验收范围；iOS 仍需 Mac/Xcode 验证。

## 1. 设计目标

面向同时管理多个交易商账户的交易终端，参考 MT5 的工作流与信息密度，不照搬其界面。图表和交易操作占据主要空间，不设计营销首页或大面积统计卡片。

- 桌面：交易商/账户、行情、图表、下单、持仓/历史在一个工作区内完成。
- 手机：同一领域状态驱动分屏导航；行情、图表、交易、账户各有入口，下单使用可展开面板。
- 默认中文，品种代码、Bid/Ask、SL/TP 等保留行业标识并提供中文说明。
- 所有端持续显示“本地模拟”，账户、报价、历史成交不得暗示来自真实市场。
- 所有金额显示币种，价格遵守品种精度，行情显示报价时间、交易商和状态。

## 2. 视觉设计

采用深蓝灰工作台、低对比结构线和蓝/铜双向行情标记。将视觉重点留给图表中的价格位置、持仓与下单预览，避免装饰性渐变、玻璃拟态、无意义动画以及满屏等尺寸卡片。

### 基础配色

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 外层工作区 | `#0F1B2D` | 导航和应用外框 |
| 图表/主体表面 | `#16263B` | 主图底色 |
| 浮层/选中表面 | `#1E3149` | 编辑和下单面板 |
| 主要文字 | `#E9F0F7` | 价格、数据、标题 |
| 主操作 | `#4C9AFF` | 选中状态和主按钮，不承担盈亏含义 |
| 结构边界 | `#304762` | 分隔线，避免过度描边 |

次要文字使用 `#A9B8CD`；图表网格比表面略亮，使用细实线。盈亏文本保持可读文字色，以正负号、方向图标和小色标辅助识别。

### 字体与间距

- 系统无衬线字体：Windows 的 Segoe UI/中文系统回退，Android 系统字体，iOS 系统字体；不依赖联网字体。
- 应用标题约 20sp，区块标题 16sp，正文和交易数据 13 至 14sp，辅助信息 11 至 12sp；价格主读数可用 24sp。
- 表格金额和价格按小数位对齐，数值列右对齐，名称与动作左对齐。
- 采用 4/8/12/16/24dp 间距，输入框约 8dp 圆角，面板约 12dp；不把所有容器做成悬浮卡片。
- 主操作触控区域不小于 44dp；桌面图表线条的命中区域大于实际绘制线宽。

### 图表方向编码

| 含义 | 色值 | 冗余编码 |
| --- | --- | --- |
| 上涨 K 线/买入方向 | `#3987E5` | 实心 K 线、向上三角、买入标签 |
| 下跌 K 线/卖出方向 | `#D95926` | 实心 K 线、向下三角、卖出标签 |
| 持仓价 | 主操作色/文字色 | 实线 + 方向、数量、仓位编号 |
| 止损/止盈 | 独立语义标记 | 虚线 + SL/TP 标签，不靠颜色区分 |
| 下单草稿 | 低透明度区域 | 虚线 + “预览”标签；与已生效仓位分开 |

蓝/铜两色已使用调色验证脚本在 `#16263B` 表面检查：亮度、彩度、色觉缺陷区分、正常视觉区分和图形对比度全部通过。最终仍需对实际文字、控件和截图进行检查。首版只交付完整深色主题，不承诺未经检查的浅色自动翻转。

│               │                                      │ 盈亏比 / 保证金    │

├───────────────┴──────────────────────────────────────┴────────────────────┤
│ 持仓 | 挂单 | 历史成交 | 活动记录                                         │
│ 品种  方向  数量  入场价  当前价  SL  TP  浮动盈亏  操作                  │

- 宽度足够时保留左侧行情栏和右侧订单面板；中等宽度时将账户和下单移至抽屉。
- 图表为弹性宽度，不挤压价格轴和右侧价格标签。
- 底部终端使用标签页；点击持仓或成交定位到对应品种和时间。
- 账户资金使用紧凑数据行，不以巨大数字抢占图表空间。

### 手机 / 窄屏

```text
┌─────────────────────────────┐
│ 交易商 / 账户     本地模拟   │
├─────────────────────────────┤
│ EURUSD   Bid / Ask           │
│ 周期  图层  数据             │
├─────────────────────────────┤
│                             │
│         可交互图表          │
│                             │
├─────────────────────────────┤
│ 当前品种持仓 / 选中交易详情  │
│          打开下单面板       │
├─────────────────────────────┤
│ 行情    图表    交易   账户  │
└─────────────────────────────┘
```

- 以可用宽度决定布局，不依赖操作系统名称。
- 长按查看十字线；选中保护线后拖动，避免与平移手势冲突。
- 保护线编辑同时提供价格输入，触控和键盘用户均可完成。
- 手机横屏/短高度窗口采用图表优先布局：顶部提供下单，资金行移至账户页，避免图表被导航和表单挤压。
- 移动端安全区、软键盘、横屏布局单独检查；iOS 检查须在 Mac/模拟器完成。

## 4. K 线与交易图层

使用共享 Compose Canvas 绘制，坐标计算提取为可独立测试的纯 Kotlin 逻辑。首版不嵌入远程 Web 图表，不依赖第三方图表服务。

- 单一时间轴和单一价格轴；显示当前 Bid/Ask、报价时间、品种价格精度。
- 周期由 TradingView 式下拉选择：分钟、小时、天预设，收藏的周期显示在工具条上，也可输入自定义周期（收藏与自定义保存在本机）；Tradovate 分钟级请求 MinuteBar，整天请求 DailyBar。由交易商提供同源历史数据，不能切周期后重新随机伪造一组历史。
- OHLC K 线、十字线、对应时间与 OHLC 读数；提供等价 OHLC 数据表。
- 品种名、周期、OHLC 与涨跌、Bid/Ask 下单按钮和成交量显示在图表左上角的悬浮图例中，不单独占用横幅，可收起为单行。周期与图层开关位于图例上方的悬浮工具条，缩放/平移按钮悬浮在时间轴上方。图例卡片不拦截平移手势，按钮处理点击。价格轴现价标签附带合约代码与当前 K 线收盘倒计时（本地模拟用模拟时钟，远程用本机时钟）。
- 支持水平浏览、缩放和“回到最新”；图表边界、空数据、单条 K 线、全等价格必须可显示。
- 当前仓位：入场水平线，方向、数量、浮盈亏标签；同品种多仓位可选中，未选中的保护线降低视觉权重。
- 历史成交：开仓/平仓方向标记，选中后展示时间、价格、成交量与实现盈亏；连接线仅在对应成交被选中时显示。
- 可单独开关历史、仓位、保护线；图例解释方向形状及 SL/TP，文本不依赖鼠标悬停才能读取。
- 历史数据缺口如实显示，不在未知区间补造已执行交易；历史窗口以外的成交从列表查看/定位。

## 5. 拖动止盈止损

交互状态：`空闲 → 选中 → 拖动预览 → 校验 → 确认 → 提交中 → 成功/拒绝`。

1. 只允许修改当前账户且具备修改权限的仓位；无对应能力时禁用并说明。
2. 指针按下后记录交易商、账户、仓位 ID、原保护价和状态版本；拖动期间固定映射范围，防止行情刷新导致价格跳动。
3. 将屏幕坐标转为价格，再按品种 tickSize 吸附；同步显示价格、价格距离、数量对应的预计盈亏。
4. 拖动本身不修改真实/模拟仓位状态；不在每个 move 事件调用交易商。
5. 松手展示确认，明确旧价、新价和预计结果；无效价格给出原因。
6. 提交时交易商重新校验当前报价、仓位状态与保护价规则；成功回执才使图层变为已生效。
7. 取消、切换账户/品种、仓位已平仓、插件断开、请求拒绝时恢复交易商确认的状态；请求 ID 防止重复执行。
8. 若行情在预览期间已经触及保护价，不能沿用过期的“有效”结果。

## 6. 下单前预览

- 买入使用 Ask 预估入场、卖出使用 Bid；使用交易商提供的合约规格与估算接口。
- 输入方向、订单类型、数量、入场价（挂单）、SL、TP；所有可选字段明确标注。
- 图表显示入场线、保护线、风险/收益半透明区域，注明“草稿预览”。
- 显示预计 SL 结果、TP 结果、盈亏比、保证金与费用；没有 SL/TP 时显示“未设置/不可计算”，不显示 0 冒充已知风险。
- 盈亏比只在预计亏损和收益均满足计算前提时显示；保本止损、盈利锁定和方向错误分别处理。
- 预估必须注明“按当前报价估算，成交以交易商回执为准”；滑点、跳空会导致实际结果不同。
- 下单必须有显式确认；默认关闭一键交易。修改方向、品种或账户后重新估算并清除旧确认状态。

## 6.1 Limit/Stop 入场线拖动

- 订单草稿：拖动入场线实时显示预计结果，松手写回表单；仍需显式确认下单，不会在图表拖动时生成订单。
- 已提交挂单：图表显示类型、方向、编号与入场线。拖动后进入改价确认框，原订单在确认前保持不变。
- 改价保持原数量、订单类型和绝对 SL/TP 价格；若新入场价使价格方向、距离或保护价失效，明确拒绝，不自动改成另一种订单。

## 6.2 草稿与挂单的 SL/TP 线拖动

- 草稿、未成交挂单、持仓的 SL/TP 线始终标注预计盈亏，起点分别是草稿入场价（市价单为买 Ask / 卖 Bid）、挂单入场价、持仓均价；交易商预估无效时仍按同一算法显示，并在图例写出原因。
- 草稿 SL/TP：松手直接回填表单，不下单。
- 挂单 SL/TP：松手进入“修改挂单止损 / 止盈”确认框，显示原价、新价和两侧预计结果；确认前订单不变。挂单列表的“保护价”按钮打开同一对话框。
- 拖动挂单入场线时，其 SL/TP 标签按移动中的入场价实时重算。
- 相近价位的标签依次右移，并避开左上角的工具条与图例，不互相覆盖。
- 改价带挂单版本，支持幂等请求；挂单在编辑期间成交、撤销或被修改时，过期编辑不能提交。
- 挂单列表提供“入场价”输入入口，与图表共用同一修改接口；支持键盘与触控替代操作。
- 邻近价格标签使用引导线错开显示，真实价格线和拖动坐标不移动。

## 6.3 图表空白处的右键菜单

- 右键落在绘图上打开绘图菜单（可拖动的订单线压在绘图上时归订单线），放置到一半的绘图则被取消；落在订单线或其标签上打开线上按钮的菜单。都不命中时，在 K 线主窗格内打开图表自己的菜单。价格轴、时间轴和指标副图上不打开。
- 菜单价位是指针所在行按最小变动单位取整的价格，与十字线价格标签一致。
- “在 X 画水平线”：直接生成一条水平线绘图并选中，可撤销。
- 限价单、突破单按能否在该价位挂住给出：买入限价须低于 Ask，卖出限价须高于 Bid，买入突破须高于 Ask，卖出突破须低于 Bid。没有报价时不给出下单项，交易商不支持的类型不给出。
- 下单项在菜单打开时确定，打开期间不随报价变化，避免指针下的项目换成反方向。
- 订单使用下单面板当前的数量，不带 SL/TP，不改动面板里的草稿；提交走下单面板同一套校验和确认（默认弹确认框，开启“跳过交易确认”后直接提交），交易商的校验不通过时不发出。
- 菜单只响应鼠标右键，触屏没有对应入口。

## 6.4 键盘下单

- 默认关闭，在「设置 → 交易」开启；设置损坏无法读取时恢复为关闭。交易商不支持市价单时不启用。
- 按键在 W / S 与 ↑ / ↓ 两组里二选一，只有选中的一组下单：W 或 ↑ 买入，S 或 ↓ 卖出。未选中的一组、← / → 移动十字线和画图快捷键都保持原样；同时按住 Ctrl、Alt、Shift 或 Meta 时不下单。
- 只有图表持有键盘焦点时按键才生效，点一下图表即获得焦点。焦点在输入框、按钮或对话框上时，按键不会到达图表，因此打字不会下单。
- 图例用一行文字说明状态：焦点在图表上时写出两个按键、订单数量和“按键后确认 / 按键即成交”，否则提示先点一下图表。图例收起时这一行仍然显示。
- 订单是市价单，数量取下单面板，不带 SL/TP，不改动面板里的草稿；提交走下单面板同一套校验和确认，交易商的校验不通过时不发出。
- 默认弹确认框，并把焦点放在确认按钮上：Enter 确认，Esc 取消。确认框关闭后焦点回到图表。
- 开启“跳过交易确认”后按键直接提交。按住按键产生的重复按键在松开前全部丢弃，一次按下只提交一单。

## 7. UI 验收

- 桌面 1440×900、1280×800 和手机约 390dp 宽不出现价格轴裁切、按钮遮挡或不可达输入。
- 键盘可以切换主要控件、提交/取消表单；鼠标/触控均可修改保护价，且有文本输入替代。
- 图表与表格读取同一仓位/成交状态；切换账户后不能显示上一个账户的交易图层。
- 非有效报价、估算中、提交中、拒绝、断开、空列表均有明确状态；按钮不允许重复提交。
- 实际截图检查标签碰撞、缩放、表格溢出；自动测试覆盖价格/坐标双向映射、吸附、手势取消和提交状态。
- 只将实际运行过的平台记为已验证；截图或 Web 原型不能替代 KMP 原生端的运行验证。
