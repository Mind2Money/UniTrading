# 子账户交易锁定

## 使用

打开「设置 → 子账户交易锁定 → 设置锁定规则」。规则属于当前登录连接下的当前交易子账户。金额使用账户币种，输入正数，支持两位小数。

- 亏损上限 200 表示券商当日总盈亏达到 -200 时触发。盈利目标 300 表示总盈亏达到 +300 时触发。普通保存时至少填写一项，两项都填则任一达到即触发。
- 「只锁定」阻止本应用开仓及改单，允许手动撤单和平仓。已经提交给券商的挂单仍可能成交。
- 「平仓并锁定」先锁定，然后撤销可能新增仓位的挂单，确认后再请求券商平仓。结果未知、未确认、断线或失败时，保留交易锁，并提示核对券商。应用不会自动重发结果未知的指令。
- 「锁定亏损 / 盈利设置」保存并冻结整条规则。必须填写有效的亏损上限。当日冻结到芝加哥时间次日零点，当周冻结到下周一零点。冻结期间不可改阈值、改动作或停用规则。
- 触发过的交易锁持续到收到更晚的券商交易日快照。盈亏回落、切换子账户、重启或停用规则均不能提前解除当日交易锁。

## 数据与适用范围

使用券商快照中的总盈亏和交易日（Tradovate）。启用规则后，对缺少新快照的子账户约每 20 秒主动拉取一次；触发时间取决于券商数据及网络，无法保证成交后实际盈亏停在阈值。应用不以余额变化、历史成交合计或本地日历替代。启用规则后，如果当前快照缺少交易日或更新时间超过两分钟，开仓和改单会暂停，等待有效数据。没有券商日盈亏和交易日的连接不能提供此功能。应用仍允许主动降低敞口的手动撤单和平仓。

本功能在设备本机执行。应用退出、系统挂起进程或券商断线时，不能持续监控或保证平仓。规则不作用于券商网站、其他终端或其他设备。卸载或清除应用数据会清除本地规则及锁定记录。已提交的订单和网络中的命令无法被本地锁追回。

## 手数、品种和一键平仓

- 在「设置 → 子账户手数与品种限制」为当前子账户单独配置。最大手数按全账户持仓绝对量、未成交的开仓挂单剩余量及拟提交量合计。保护单不计入。例：持仓 3 手、开仓挂单剩余 1 手、上限 5 手，最多再下 1 手。
- 禁用品种可按根代码或具体月份配置。MES 覆盖 MES、@MES 和 MES 的月份合约，不影响 ES；MESZ6 仅限制这个月份。手动撤单和平仓仍可用。
- 「账户 → 交易」提供当前子账户一键平仓和全部子账户一键平仓。全部范围为本应用各登录连接当前列出的子账户，确认框逐一列明。两种操作都包含未成交挂单，确认按钮在左、取消在右，即使开启跳过交易确认也必须单独确认。
- 应用等待券商确认每笔撤单或平仓，再处理后续命令。未确认的账户会单独列出，其他账户继续处理。执行期间本应用暂缓该批目标账户的新交易命令。

## 构建

源码基于上游 main 的 ccd820612281aaa617293cb80cce7971c7335bac（1.5.0）。本地测试 APK 使用独立包名 com.unitrading.demo.risk.test 和调试签名。可与旧版并存，应用数据分开。沿用上游激活流程。

安装 JDK 21 和 Android SDK Platform 37.0、37.2。构建内置登录浏览器 APK：

```powershell
.\gradlew.bat :androidApp:assembleGeckoDebug
```

APK 输出目录是 androidApp/build/outputs/apk/gecko/debug。构建任务不发布文件。
