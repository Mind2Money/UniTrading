# 跟单 Demo 验证版

基于 v1.8.3 主分支的开发版。设置入口为「设置 → 交易 → 账户跟单」；旧版按净仓变化跟随的控制器及其监控入口已删除，新跟单功能当前无法启动。目标是只跟随 UniTrading 内的主账户交易，支持同登录的 Demo 和 Live、逐笔固定数量或倍率，以及挂单和保护单的完整生命周期。用户要求的完整功能仍在开发，不能将本草稿视作已完成。

新版规划器按用户确认的规则区分每次成交：固定模式每次部分成交使用固定张数，倍率模式按成交张数计算；主账户平仓时跟随账户平仓，反手先平后开，超过上限或仓位不匹配则停止。限价及止损挂单按相同价格独立提交；各账户成交可能不同步，已独立提交的挂单不再对主单成交重复下市价单。来源登记、持久日志、挂单规划及 Demo 市价/挂单发送服务均为独立原型，目前没有接入交易入口。修改、撤销、保护单关联和异常恢复仍需实现。

订单执行条件使用同一券商账本的快照版本，在命令发送前由 Tradovate 适配器复核；订单标记为自动交易。跟单模式下不允许跟随账户的金额保护自动改写订单。券商数据模型、行情及事件仍需在真实 Tradovate Demo 环境逐项验证；模拟器通过不代表券商支持或实盘可靠。在完整订单生命周期和异常恢复经过验证之前，保持 Live 禁用。

已确认的目标行为：手动启动前所选主账户和跟随账户全部空仓且无挂单；单个跟随账户发生拒绝、结果未知或自身保护单先触发时，只暂停该账户；断线或程序重启后，只有相关账户状态和完整成交记录核对一致、没有未确认操作时才能自动恢复。若主账户状态无法确认，则不能安全恢复任何跟随账户。无效的跟随保护价格不能自动改价或平仓。主账户、跟随账户和各自手数设置应在本机保存；此前已保存的设置不等于启动跟单。

跟单范围为所有合约，每个跟随账户使用自己的固定手数或倍率设置。跟随账户暂停期间的交易不补发；仓位或挂单不一致时保持暂停，须核对处理后才能恢复。这些是目标行为，尚未接入运行时。

用户选择：主账户止盈止损先成交时，即使只部分成交，也撤销跟随账户对应保护单并市价全平；撤单失败或结果不明时暂停该跟随账户，确认撤单后才能平仓。跟随账户全平但主账户仍有仓位时，保持暂停并提示核对。跟单记录无法保存时，暂停受影响跟随账户，主账户交易继续。平仓流程必须依据券商确认和持久日志设计，避免与未撤销的保护单重复成交；目前尚未接入运行时。

保存跟单设置前检查当前所选主账户和跟随账户。数据完整且发现持仓或挂单时，展示所有选中账户及其持仓、挂单数量；用户选择“否”时退出，不保存本次设置，原有设置保持不变。选择“是”才调用已有批量账户处理接口撤单并平仓，未选账户不处理；结束后重新核对，全部确认完成后才保存本次设置。账户检查及清理均依赖通用券商会话接口；其他券商未来还需要提供完整的持仓、挂单快照和相应交易能力。当前跟单功能未完成，确认清理也不会启动跟单。

新增的主账户保护操作日志、跟随保护执行器、逐账户恢复核对与设置保存目前仍是独立部件，未完成交易界面、成交事件流和断线恢复的端到端联动。Tradovate 的平仓回执可能不含订单 ID；不得将合约 ID 当作平仓订单 ID。券商成交历史的完整性和跨交易日恢复尚未验证，在完成前不能自动补发或声称能自动恢复。
