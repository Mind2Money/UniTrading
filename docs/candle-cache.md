# K 线增量缓存

Tradovate 图表按环境、用户、品种、周期保存最近 2,000 根 K 线。连续品种（例如 `@MES`）与交割合约使用不同缓存键；自定义周期按分钟数区分。

- 首次打开或缓存不可用时，请求最近 2,000 根。
- 切换回已缓存图表、重新登录或重启后，先显示缓存，再从最后一根的时间戳补取至最新，并接续实时流。末根重复请求，用服务端最新 OHLCV 覆盖同时间戳记录。
- 同一图表已订阅时，重复 `watch` 保留现有图表流；所需报价订阅仍会更新。
- 历史包按时间排序、去重；同次订阅中实时更新优先于晚到的历史包。单页结束后若尚未接上缓存末根，继续向前补页；接上末根或本轮取得完整的最近 2,000 根后，才推进缓存。空页、重复边界、失败或中途取消不推进检查点。
- 行情更新合并后延迟 1 秒写入，正常断开连接时补写待保存数据。异常退出可能使末次更新尚未落盘，下次仍从已保存的末根补取。
- 损坏、不支持版本、乱序、重复时间或未来时间的缓存不使用。缓存读写失败不阻断行情或交易；写失败时仍可复用内存数据。
- 早到数据缓冲溢出时不推进缓存。订阅请求超时或旧订阅清理超过总计 5 秒时，关闭并重建行情连接，回收尚未确认的服务器订阅。

缓存通过应用现有 `SnapshotStore` 落盘，键以 `candles-v1-` 开头，不包含访问令牌。Desktop/Android 使用现有原子文件写入；平台存储适配器在后台调度器上执行。缓存只提供图表历史，交易就绪和下单价格仍由实时行情链路控制。

时间范围字段与订阅 ID 按 [Tradovate Market Data API](https://api.tradovate.com/) 处理。缓存命中时用 `asMuchAsElements: 1` 保持实时流，另用 `asFarAsTimestamp` 和 `closestTimestamp` 补取缺失区间；分页沿最早时间回退，完成后取消历史页的订阅并保留实时流。分页方式参考 [Tradovate 官方示例](https://github.com/tradovate/example-api-faq/blob/main/docs/HowToHandleDataSizeLimits.md)。未命中时请求 `asMuchAsElements: 2000`。

自动验证包括缓存恢复、周期切换、末根覆盖、请求取消竞态、历史/实时共享订阅 ID、乱序合并、未完成历史不推进缓存及磁盘失败降级。测试使用模拟行情连接，不代表真实账户联调结果。
